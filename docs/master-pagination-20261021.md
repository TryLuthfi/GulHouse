# Master data pagination and lazy edit (local)

Properti, Tipe Kamar, Kamar, and Penghuni now use SQL pagination with allowed sizes 10, 25, 50 and 100. Filtering and whitelisted sorting run in the database, with deterministic ID tie-breakers. An aggregate query over the same filtered SQL source supplies summary totals independently of the current page. Invalid page options are normalized and excessive pages clamp to the last page. Photo management is a gallery rather than a data table and retains its existing gallery workflow.

Initial pages render only the create form. Edit fetches one authenticated, non-cacheable modal from `master-form/{resource}/{id}`. Existing write endpoints, saved IDs, full form fields and validation are retained. Current archived references are included when loading an existing form. Tenant listings select one emergency contact deterministically so duplicated contacts do not duplicate stays; full identity data is fetched only for editing.

Security_hook recognizes read-only modal GET requests while preserving module authorization. Viewer accounts cannot fetch edit forms. The hook injects CSRF inputs into modal fragments, and all original POST security remains enforced. The frontend reinitializes confirmations, money fields, region cascades, accessible dialog names and focus restoration for dynamically loaded forms. Loading and error messages are provided. Metric links navigate normally to avoid stale reference catalogs.

CIKO isolated tests passed 285 model checks, eight security-hook checks, and 79 real HTTP checks, including actual CSRF-protected saves on all four forms and rejection without a token. Root independently tested page changes, filtered summaries, per-page selection and lazy forms on the real local read-only pages, and a browser Edit -> confirm -> successful save on a synthetic type record. No real business forms were submitted. Pagination footer variable leakage, missing closure capture, and fragment CSRF/accessibility issues were fixed before completion.

Final readback passed 48 checks: all 47 existing tables retain exact original row counts and hashes, including occupants, contracts, payments and history. Together with the 285 model, eight security and 79 HTTP checks, the audited total is 420 passed checks. The owned synthetic schema was removed, its temporary credentials deleted, and its loopback PHP server was confirmed stopped. No schema migration or production deployment is part of this change.
