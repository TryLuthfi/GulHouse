# Local geography through district

GulHouse now owns copies of three reference tables from local `databasetkm_com`: `gh_region_provinces` (34), `gh_region_regencies` (514), and `gh_region_districts` (7,215). No village table is copied. Runtime GulHouse does not query DatabaseTKM.

Master Properti provides province, regency/city, district, and a manual full address for GH/house properties. Master Kamar provides the same fields for apartment units, while APT remains one property. Unrelated location sections are hidden and disabled. Changing a parent resets its descendants; the server independently checks both parent relationships and requires a complete valid chain once a selection is supplied.

Existing city and address values remain untouched during migration. Nullable `region_province_id`, `region_regency_id`, and `region_district_id` fields are added to properties and rooms, with no inferred matching. Empty legacy forms and clients that omit the new fields preserve existing IDs/cities/addresses. Once selected, the existing city display field is derived from the chosen master city so landing and older clients retain compatibility. Full addresses remain manual, including kelurahan, street, building/tower, floor and unit details.

## Backup and preservation

Local migration entry point: `scripts/import-gulhouse-regions.php`; defaults to a read-only plan, `--apply` performs backup then import. It only permits localhost and the local GulHouse or owned test schemas. Source data is checked for missing parents, and a nonempty conflicting destination blocks replacement. All preexisting table values are compared before commit. Reference tables use their own parent foreign keys; no business relationship or ID is reassigned.

Actual SQL and JSON backup directory:
`.e2e/regions-20261021/20261021-050941-01f1ef/`

All 44 original tables preserve exact old values and counts, including 84 rooms, four properties, occupants, contracts, billing, payments and history. Original row timestamps remain identical. The only new business-table values are null administrative IDs. Reference copies are independent of DatabaseTKM.
